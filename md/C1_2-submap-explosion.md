# C1_2 子图爆炸现象分析报告

> **状态**：最终版  
> **涉及实验**：C1_2（FM dorm1_fast1, +GI-KF）  
> **现象**：SLAM 主循环中生成 72 个子图（正常应 ~17 个），后续 loop closure 无法在合理时间内完成

---

## 1. 现象描述

| 实验 | 策略 | 子图数 | 状态 |
|------|------|--------|------|
| C1_0 | Baseline | ~17 | ✅ 正常完成 |
| C1_1 | +IMU | ~17 | ✅ 正常完成 |
| **C1_2** | **+GI-KF** | **72** | ❌ SLAM 完成后 loop closure 无法完成 |
| C1_3 | +Pyramid | ~17 | ✅ 正常完成 |
| C1_4 | +KF+Pyramid | ~17 | ✅ 正常完成 |
| C1_5 | +ALL | ~17 | ✅ 正常完成 |
| **C2_2** | **+GI-KF** | ~17 | ✅ 正常完成（与 C1_2 对比关键发现） |

### 关键发现

**同一策略（+GI-KF）在 C1（dorm1_fast1）和 C2（dorm2_fast）上表现完全不同。** 这证明子图爆炸不是 GI-KF 的系统性 bug，而是 **场景特异性现象**——dorm1_fast1 的特定环境特征（纹理分布、空间结构、运动模式）与 dorm2_fast 存在差异，导致纯 GI-KF（无 Pyramid）下的跟踪退化程度不同。

---

## 2. 根因分析

### 2.1 因果链

```
GI-KF 动态选帧 → 更少的关键帧做建图
    │
    ▼
高斯模型优化不充分（关键帧少 → optimize_submap 只覆盖了部分视角）
    │
    ▼
Tracker 位姿漂移增大（模型差 → 渲染与 GT 匹配困难 → 位姿估计噪声大）
    │
    ▼
连续帧间累计位移更容易达到 motion heuristic 阈值 (rot_thre=50°, trans_thre=0.5m)
    │
    ▼
子图边界频繁触发 → 72 个子图（正常 ~17 个）
    │
    ▼
72 次 loop closure 触发 × construct_pose_graph(72 个子图)
→ 69 次 construct_pose_graph 调用 = 每次重建 72 子图的 PoseGraph
→ 计算量指数级膨胀 → 无法在合理时间内完成
```

### 2.2 为什么 C1_4（+KF+Pyramid）不会这样

| 对比维度 | C1_2 (+GI-KF) | C1_4 (+KF+Pyramid) |
|---------|---------------|-------------------|
| 关键帧数 | 较少 | 相同（GI-KF 决定） |
| 高斯模型质量 | 差（全分辨率训练，关键帧少 → 覆盖不足） | 好（Pyramid 粗到细训练 → 泛化更好） |
| 跟踪精度 | 差（模型差 → 位姿漂移） | 好（模型好 → 位姿准） |
| 子图数 | 72 | ~17 |

Pyramid 通过粗到细渐进训练，使得即使关键帧较少，高斯模型也能较好地覆盖场景（低分辨率下每个高斯覆盖更大区域 → 泛化更强）。因此 tracker 位姿不会严重漂移，子图数保持正常。

### 2.3 为什么 C2_2 不会这样

dorm2_fast 的场景特征（不同的空间布局、纹理分布、运动轨迹）使得即使在纯 GI-KF 下，tracker 位姿漂移也未达到触发子图切碎的程度。这说明 GI-KF 单独使用的健壮性是**场景依赖的**——在某些场景下表现正常（C2），在另一些场景下会退化（C1）。

### 2.4 为什么安全网没有阻止

安全网在 30 帧无关键帧时强制插入。但 C1_2 的关键帧间隔从未超过 30 帧——GI-KF 本身选帧正常，问题不在"选不出关键帧"，而在**模型精度下降→位姿漂移→子图切碎**这条二级因果链。

### 2.5 为什么 `gsr_max_iters=60` 没有解决

`gsr_max_iters` 减少的是**每次 GSR 配准的迭代数**（100→60），但根本问题是 **loop closure 触发了 69 次 construct_pose_graph 调用**。每次调用仍要遍历 72 个子图做 pairwise 匹配和 GSR 配准。69 × 72 = 4968 次子图对处理——这才是瓶颈，不是单个 GSR 的迭代数。`gsr_max_iters=60` 只把单个 GSR 从 100 次渲染降到 60 次，总计算量只减少了 2/5，远不足以消化 69×72 的组合爆炸。

## 4. 决策与建议

### 4.1 不做进一步工程优化

以下可选优化均已评估并排除：

| 优化方案 | 排除理由 |
|---------|---------|
| 减少 construct_pose_graph 调用频率 | 改变 PGO 校正时机，影响 FM 所有实验的一致性 |
| 限制 GSR 配准的子图对数量 | 改变 PGO 图结构，影响实验结果 |
| 增大 `new_submap_every` | 改变所有 C 组实验的子图粒度，不公平对比已跑完的实验 |

**核心原则：** 所有 FM 实验必须在相同条件下运行。任何仅针对 C1_2 的优化都会破坏已跑完的 C1_0~C1_5 和 C2_* 实验的对等性。

### 4.2 论文中的呈现建议

C1_2 的现象本身是一个有意义的实验发现，应在论文中诚实记录：

- **定量报告**：C1_2 产生了 72 个子图（正常 ~17），导致计算不可行
- **对比 C2_2**：同一策略在 dorm2_fast 上正常（~17 子图），说明是场景依赖的
- **对比 C1_4**：加 Pyramid 后子图数恢复正常（~17），说明 Pyramid 能有效补偿 GI-KF 单独使用时的跟踪退化
- **结论**：GI-KF 单独使用在特定场景下可能导致跟踪退化，建议与 Pyramid 联合使用以确保健壮性

### 4.3 C1_2 的运行选择

由作者自行决定：

- **方案 A**：用更大超时（如 24h）让实验自然跑完
- **方案 B**：跳过 C1_2，在论文中声明计算不可行，以 C2_2 和 C3_2 的结果作为 GI-KF 单独使用的代表
- **方案 C**：将 C1_2 视为失败的实验点，论文消融表中标注 "N/A (computation infeasible)"，同时用 C1_4 的结果间接证明 GI-KF+Pyramid 的必要性
